# حدود المحتوى والعمليات في Orbix

## القرار

- Strapi هو مصدر الحقيقة للمقالات والخدمات والصفحات التسويقية وحقول SEO فقط.
- Firebase القديم يبقى مصدر الحقيقة للمستخدمين والعقارات والفنادق والحجوزات والطلبات.
- React يقرأ المحتوى من Strapi ويستمر بعرض صفحات العقارات والفنادق العامة من Firebase لتحسين الوصول وSEO.
- Flutter يستمر بالعمليات الحالية على Firebase خلال هذه المرحلة.
- NestJS يبقى مجمداً كخيار مستقبلي ولا يدخل في مسار المحتوى الحالي.

## عقد نشر العقار القديم

العقار قابل للعرض العام فقط عندما يتحقق الشرطان معاً:

1. `status == "approved"`
2. `isVisible == true`

الموافقة تعني أن العقار اجتاز المراجعة، والظهور مفتاح مستقل يمكن للإدارة إيقافه دون إلغاء الموافقة. يمنع تغيير هذين الحقلين أو ترجمتهما إلى `published` خلال مراحل Strapi.

## الممنوع في Strapi

لا ننشئ في Strapi جداول للمستخدمين أو العقارات أو الفنادق أو الحجوزات أو العقود أو المدفوعات. ولا نضع مفاتيح Firebase أو Stripe السرية في React أو Flutter.

## ترتيب التنفيذ

1. تشغيل Strapi محلياً مع PostgreSQL وإنشاء المدير الأول.
2. تفعيل `find` و`findOne` فقط للدور Public للأنواع Article وService وPage.
3. ضبط `VITE_STRAPI_URL` في Cloudflare وبناء React.
4. تنفيذ Smoke Test للمقالات والخدمات مع بقاء صفحات العقارات والفنادق تعمل من Firebase.
5. بعد ثبات المحتوى، تبدأ مرحلة الدفع في خدمة Server-side مستقلة.
